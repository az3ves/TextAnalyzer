# TextAnalyzer

Обновление 06.11.2026: по умолчанию включён простой ручной поиск фрагментов через кнопки Яндекса и Google, без API и регистрации. Автоматического процента плагиата в этом режиме нет. Сервер не обращается к поисковикам; запрос отправляется из браузера только после нажатия ссылки.


Веб-приложение для анализа русскоязычных текстов: читаемость, сравнение двух текстов, сходство стиля, поиск персональных данных и выборочный поиск совпадений в интернете. Детектора ИИ нет.

## Запуск на Windows

Проверено на Python 3.12.14. Установите Python с python.org с компонентом pip.
В папке проекта выполните:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Активация окружения не обязательна. Откроется http://127.0.0.1:5000.
На Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.
Для запуска без браузера задайте `OPEN_BROWSER=0`. Адрес и порт: `HOST`, `PORT`.

## Работа

1. Вставьте текст или добавьте файл кнопкой «+». Проверьте извлечённый текст.
2. Нажмите «Отправить». Откройте список исключённых из подсчётов строк при необходимости.
3. Выберите проверки. Для уникальности и стилометрии нужен второй текст.
4. Нажмите «Проверить». Результаты сохраняются вместе с исходным текстом в истории.
5. В безопасности снимите галочки с находок, которые хотите оставить, и нажмите «Очистить текст». Появится отдельная копия, исходная запись сохранится.

После редактирования основного текста его нужно отправить заново. Второй текст не сохраняется, при открытии истории поле очищается. «Очистить» в истории показывает диалог подтверждения. История привязана к случайной cookie этого браузера: удаление cookie лишает доступа к старой истории. Это не система учётных записей.

## Файлы и OCR

Поддерживаются TXT/MD (UTF-8, UTF-16 с BOM, Windows-1251), DOCX, PDF с текстовым слоем, PNG/JPEG/BMP/TIFF/WebP. Файл до 20 МБ, текст до 2 млн символов. Другие кодировки не гарантируются. Заголовки Word помечаются `#`, таблицы — `|`, чтобы исключить их из языковых метрик; порядок блоков сохраняется. Распознавание структуры обычного текста и PDF эвристическое.

Для фото отдельно установите [Tesseract OCR](https://tesseract-ocr.github.io/tessdoc/Installation.html) и языковые данные `rus` и `eng`. При другом пути задайте `TESSERACT_PATH`. В `OCR_LANGS` по умолчанию `rus+eng`. Программа сначала проверит наличие языков. OCR ограничен 30 секундами на изображение. Многостраничные TIFF загружайте по одной странице.

PDF со страницами без текста не анализируется частично и незаметно: приложение предлагает загрузить такие страницы как фотографии. Встроенного OCR скан-PDF нет. Результат OCR зависит от качества фото, шрифта и наклона, его необходимо проверять вручную.

## Что означают результаты

- Читаемость: ориентировочные индексы. SMOG и Coleman–Liau используют исходные англоязычные формулы и не определяют школьный класс для русского языка.
- Уникальность: доля неповторяющихся последовательностей из четырёх слов относительно конкретного второго текста; не процент оригинальности во всём интернете.
- Стилометрия: косинусное сходство частот служебных слов и пунктуации. Пороги эвристические, авторство не устанавливается. Нужно от 50 слов на текст, менее 500 — предупреждение.
- Безопасность: регулярные выражения, контрольные суммы СНИЛС и карт, модель Natasha для имён. Возможны пропуски и ложные срабатывания; гарантии обезличивания нет. Если Natasha не запускается, остальные категории продолжают проверяться.
- Дополнительный серверный режим (SEARCH_MODE=duckduckgo): до шести разных предложений из разных частей текста, до 12 слов в запросе. Сравниваются последовательности из шести слов в сниппетах выдачи. Полные страницы сайтов не скачиваются. Поиск может занять около минуты. Фрагменты уходят в DuckDuckGo только при выборе этой проверки.

## Дополнительный серверный режим и его ограничения

По умолчанию SEARCH_MODE=manual: приложение только готовит фрагменты и ссылки, пользователь просматривает источники вручную. Автоматическая проверка DuckDuckGo оставлена как необязательный старый режим и может блокироваться. Следующий абзац описывает испытание этого старого режима.

05.11.2026 реальный запрос DuckDuckGo вернул HTTP 200 с явной пустой выдачей, следующий — HTTP 202 (ограничение). Положительный результат на реальной выдаче в этой среде не подтверждён. Разбор HTML, совпадение сниппетов, регистр запросов и частичные отказы проверены автоматическими тестами и локальным HTTP-сервером. Блокировка, CAPTCHA и незнакомая страница показываются как «не проверено», а не как «совпадений нет».

`SEARCH_URL` позволяет выбрать совместимый HTML/Lite endpoint DuckDuckGo или собственный тестовый сервер. Это не универсальный адаптер к любому поисковику. Для стабильной работы на публичном сервере нужен отдельный провайдер с официальным API; его ключ в проект не включён.

## Проверки

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

43 теста проверяют входные данные, сохранение и изоляцию истории, параллельные записи SQLite, реальную Natasha, очистку, DOCX/PDF, кодировки, ошибки OCR и поиск через настоящий локальный HTTP-сервер. Внешний интернет не нужен для автотестов. Настоящий OCR в этой среде не проверен: Tesseract отсутствует; в тестах адаптера использована заглушка.

## Хостинг

На Linux используйте `gunicorn --workers 2 --threads 2 --timeout 120 app:app` (Procfile включён). Gunicorn не запускается на Windows; для локального режима используйте run.py. Встроенный сервер Flask предназначен для локального запуска.

SQLite по умолчанию находится в `instance/history.db` рядом с приложением. На хостинге задайте `TEXTANALYZER_DB` абсолютным путём на постоянном диске и обеспечьте доступ на запись. Эфемерная файловая система не сохраняет историю после пересоздания контейнера. Для нескольких серверов понадобится общая БД. HTTPS настраивается на стороне хостинга. Публичный хостинг в рамках проверки не развёрнут.

Исходные тексты и результаты хранятся в SQLite в открытом виде. Удаление записи — логическое удаление из SQLite, не гарантированное стирание с носителя. Для конфиденциальных документов используйте локальный запуск и отключайте интернет-проверку.

## Файлы проекта

`app.py` — API и запуск проверок; `readers.py` — извлечение текста; `text_utils.py` — слова, предложения и структура; `complexity.py`, `uniqueness.py`, `stylometry.py`, `plagiarism.py`, `security.py` — проверки; `storage.py` — транзакции SQLite; `config.py` — параметры; `errors.py` — понятные ошибки; `templates/index.html`, `static/` — интерфейс; `tests/test_app.py` — регрессионные проверки.
